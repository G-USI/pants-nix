# pants-nix

The [Pants](https://www.pantsbuild.org/) build system on NixOS — **without
an FHS sandbox**. Pants runs Nix-native: the official release wheel's
native engine is patchelf'd against Nix libraries at build time, and
runtime-downloaded tools in Pants' caches are patched in place
(idempotently) by a wrapper hook.

Every stable Pants release from **2.21.0 through 2.33.1** is packaged —
per-version interpreter (python3.9 / 3.11 / 3.14 as the release wheel
dictates), per-version dependency closure taken from the Pants repo's
own `user_reqs.lock` at that tag.

## Usage

Ad-hoc (defaults to the newest packaged release):

```console
$ nix run github:G-USI/pants-nix -- --version
```

Every version is exposed as `packages.pants-<ver>` (dots → underscores):

```console
$ nix shell github:G-USI/pants-nix#pants-2_21_1 --command pants --version
```

In a flake:

```nix
{
  inputs.pants-nix.url = "github:G-USI/pants-nix";

  outputs = { self, nixpkgs, pants-nix }: {
    devShells.x86_64-linux.default =
      let
        pkgs = nixpkgs.legacyPackages.x86_64-linux;
        pkgs39 = pants-nix.inputs.nixpkgs-py39.legacyPackages.x86_64-linux;
      in
      pkgs.mkShell {
        packages = [ (pants-nix.lib.mkPants pkgs pkgs39 { version = "2.31.0"; }) ];
      };
  };
}
```

Driven by your repo's `pants.toml` (re-resolves when you bump
`[GLOBAL].pants_version`):

```nix
pants-nix.lib.fromPantsToml pkgs pkgs39 ./pants.toml
```

Unknown versions fail loudly — run the generator (below) to add one.

## How it works

- `pants/versions.nix` maps every packaged version to its release-wheel
  URL, SRI hash, interpreter tag and dependency closure. All of it is
  generated by `scripts/gen-versions.sh` (driver) + `scripts/generate.py`
  (nix-backed Python): it enumerates stable GitHub releases, prefetches
  the x86_64 manylinux wheel, reads `Requires-Dist` from the wheel's
  METADATA, and expands the **transitive closure** through the Pants
  repo's `user_reqs.lock` at that tag — using the lock's own artifact
  URLs and sha256 hashes. Re-run to pick up new Pants releases.
- Each package pip-installs the release wheel + closure onto the Nix
  interpreter matching the wheel's CPython tag; `autoPatchelfHook`
  rewrites the native engine (`pants/bin/native_client`) and native
  extensions against Nix libs. cp39-era releases (2.21–2.24) build
  against the hydra-cached `nixpkgs-py39` input (python3.9 left
  unstable after EOL); cp311 (2.25–2.31) and cp314 (2.32+) use the
  main nixpkgs.
- The `pants` binary is a `python -m pants` wrapper with
  `NO_SCIE_WARNING=1` (Pants otherwise refuses non-scie launches).
- Wheels record no exec bits and the loaders `chmod()` embedded
  binaries next to themselves — both are handled at build time
  (pre-chmod + guarded loader patches for both the <=2.31 and 2.32+
  loader shapes), because the store is read-only.
- Pants' external tools (rustup-managed Rust toolchains, and the
  scie-era `~/.cache/nce` interpreters reused by PEX venvs) land as
  generic-Linux binaries. The wrapper runs `pants-patch-caches` on
  launch: interpreter rewrites **append** the Nix lib dir to existing
  rpaths (never replace — self-contained trees carry their own), and
  shared objects are rpath-patched **only when `ldd` shows unresolvable
  needs** (blanket rewrites corrupted large mypyc modules). Stamp-
  guarded, atomic, backgrounded; disable with `PANTS_NIX_AUTOPATCH=0`.
- Extra interpreters (e.g. `python314`) can be exposed via
  `extraPythons` so Pants' interpreter search can satisfy user
  resolves. Give Pants the interpreters your repo's tool resolves
  need — tool venvs are cached per constraints and reused.

## Limitations

- x86_64-linux only.
- One interpreter per Pants version (the release wheel's CPython tag).
- Fully-hermetic (no-network) nix builds of *user* resolves are out of
  scope: Pants downloads distributions at runtime like it always does.
